# Decisions

One entry for each design change. Newest first.

- 2026-10-18: Phase 2 review (one `code-reviewer` subagent): fixed the CRITICAL finding (the fallback deleted the spot Job before it checked the fallback name, so a name conflict left nothing running and no retry; now it creates or adopts `<name>-od` first, and retries on a conflict), the HIGH finding (a repeated attempt after a failed status write duplicated a map-list key; `recordAttempt` now updates in place), the MEDIUM finding (a scale floor of 10 % for "start now" means near 0) and both LOW findings (one boundary rule for "time for a spot run"; the demo script stops when the kustomization file has local changes).
- 2026-10-18: The planner scales each signal by its "start now" mean, not by min-max over the candidates. Reason: found while preparing the demo, a plan showed `savingsPercent` -5. Min-max scaling gives a signal that barely moves (for example a spot price) the same pull as a signal with large swings, and the chosen window could be worse than "start now" in real terms. With the new scale, the planner maximizes the reported weighted saving, so the saving is never negative.
- 2026-10-18: The printer columns "Planned start" and "Deadline" are strings, not dates. Reason: kubectl prints a future time in a date column as `<invalid>`, and both times are usually in the future.
- 2026-10-18: Replaced the planned `entsoe` series `CarbonEstimate` with a new provider `energyCharts`. Reason: without an ENTSO-E token, the generation forecast documents cannot be checked, and the fixtures would be guesses. Energy-Charts gives a renewable-share forecast for 16 European countries without a key, and a live test checks it. The ENTSO-E carbon estimate is now in "Later".
- 2026-10-18: Added design section 8 (phase 2). Reason: the goal is to save cloud money and carbon, with free and open data only, in any region, and with Argo Workflows. Cloud prices change very little with the time of day, so the money part uses spot capacity with an on-demand fallback before the deadline. The carbon part maps cloud regions to free data sources, with an Open-Meteo weather proxy as the global fallback. Argo Workflows uses its `resource` template, so offpeak needs no Argo code.
- 2026-10-17: Removed `spec.electricityMaps.baseURL` from `SignalSource`. Reason (review finding, HIGH): `SignalSource` is cluster-scoped, and the token comes from a Secret in the controller namespace. A user who can write a `SignalSource` could set a base URL on their own host and receive the token (confused deputy). The provider keeps a base URL in code for tests only. If another API version is necessary later, make it a controller flag, not a user field.
- 2026-10-17: Accepted review findings without a change: the response caches have no request de-duplication, because the controller runs one reconcile at a time (`MaxConcurrentReconciles` 1). Add `singleflight` if the concurrency goes up. The `deferrablejobs/finalizers` `update` permission stays, because `blockOwnerDeletion` on the owned Job needs it when the OwnerReferencesPermissionEnforcement admission plugin is on.
- 2026-10-17: The `awsSpot` provider calls the EC2 Query API directly and does not use the SDK EC2 client (`service/ec2`). It uses only `aws/signer/v4` and `config` from the AWS SDK for Go v2. Reason: `service/ec2` is 30 MB of generated code for one API action. Its compile needs more memory than the build host has, and it makes CI builds and the image larger. The direct call is about 60 lines and has a wire-level test with a SigV4 check.
- 2026-10-17: Install the CRDs with server-side apply (`kubectl apply --server-side`). Reason: the `DeferrableJob` CRD embeds the full Job template and is about 750 KB. Client-side apply stores the object in an annotation with a 256 KB limit. Server-side apply keeps the field descriptions for `kubectl explain`.
- 2026-10-17: Planner step 2 starts at `earliest`, not at "now". Reason: `notBefore` is a hard limit from the user. If the deadline is at risk, the Job starts as soon as `notBefore` allows. Also defined the neutral value range and the `savingsPercent` formula (section 4, steps 4 and 8), because the old text did not define them.
- 2026-10-17: Karpenter NodePools are read as `unstructured`. Reason: the Karpenter Go module has a large dependency tree, and offpeak needs only a few fields.
- 2026-10-17: Signal sources are a cluster-scoped CRD, not a controller config file. Reason: GitOps management, schema validation, and no controller restart for a change.
- 2026-10-17: Unknown future slots use an hour-of-week median from 14 days of history, then a neutral fill. Reason: day-ahead prices cover at most about 35 hours, and AWS spot prices have no forecast.
